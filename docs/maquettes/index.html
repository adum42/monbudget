monbudget → app de gestion complète

Six idées d'évolution à partir de l'existant (transactions, catégories, comptes, soldes manuels, stats). Chaque page est une maquette cliquable avec de fausses données ; les pages 2 et 4 sont interactives.

Idée 1 · fondation

Multi-comptes & soldes

Chaque transaction rattachée à un compte. Une carte par compte : solde calculé, solde banque, écart, date du dernier rapprochement.

 Idée 2 · cœur du besoin

Pointage & rapprochement

Tu saisis le solde du relevé, tu coches les opérations, l'app calcule l'écart en direct. Écart = 0 → mois verrouillé.

 Idée 3

Suivi de l'épargne mensuelle

Combien j'ai mis de côté chaque mois, sur quel livret, taux d'épargne, objectif mensuel et cumul annuel.

 Idée 4 · ta demande

Cagnottes par thème

Apport appart, Noël, vacances… réparties virtuellement sur tes livrets, avec versement mensuel conseillé pour tenir la date.

 Idée 5

Budgets & récurrences

Plafond par catégorie suggéré à partir des mois précédents, opérations récurrentes (loyer, abonnements, salaire) et solde prévisionnel de fin de mois.

 Idée 6

Clôture du mois & import

Checklist mensuelle qui garantit que tout est rentré, import CSV de la banque avec détection des oublis et doublons.

Évolutions du schéma Supabase

-- 1. Rattacher chaque opération à un compte + statut de pointage
ALTER TABLE transactions ADD COLUMN compte_id     bigint REFERENCES comptes(id);
ALTER TABLE transactions ADD COLUMN compte_dest_id bigint REFERENCES comptes(id); -- pour les 'mouvement'
ALTER TABLE transactions ADD COLUMN statut text DEFAULT 'saisi'
      CHECK (statut IN ('prevu','saisi','pointe','rapproche'));
ALTER TABLE transactions ADD COLUMN date_valeur date;   -- date de passage en banque

-- 2. Comptes typés
ALTER TABLE comptes ADD COLUMN type text DEFAULT 'courant'; -- courant | epargne | especes | credit
ALTER TABLE comptes ADD COLUMN couleur text, ADD COLUMN archive bool DEFAULT false;

-- 3. Rapprochements (remplace / complète la table soldes)
CREATE TABLE rapprochements (
  id bigserial PRIMARY KEY, compte_id bigint REFERENCES comptes(id),
  date_releve date, solde_releve numeric(12,2), solde_pointe numeric(12,2),
  ecart numeric(12,2), valide bool DEFAULT false, created_at timestamptz DEFAULT now());

-- 4. Cagnottes thématiques
CREATE TABLE cagnottes (id bigserial PRIMARY KEY, nom text, emoji text, couleur text,
  objectif numeric(12,2), date_cible date, compte_id bigint REFERENCES comptes(id), archive bool DEFAULT false);
CREATE TABLE cagnotte_mouvements (id bigserial PRIMARY KEY, cagnotte_id bigint REFERENCES cagnottes(id),
  date date, montant numeric(12,2), transaction_id bigint REFERENCES transactions(id), note text);

-- 5. Budgets et récurrences
CREATE TABLE budgets (id bigserial PRIMARY KEY, categorie_id bigint REFERENCES categories(id),
  mois date, plafond numeric(12,2));            -- mois NULL = budget par défaut
CREATE TABLE recurrences (id bigserial PRIMARY KEY, description text, montant numeric(12,2), type text,
  categorie_id bigint, compte_id bigint, jour_du_mois int, frequence text DEFAULT 'mensuel', actif bool DEFAULT true);
Point clé : aujourd'hui le solde par compte repose sur solde_initial + saisies manuelles dans soldes. Avec compte_id sur les transactions, le solde devient calculé (solde initial + somme des opérations), et la table soldes devient la vérité banque à laquelle on compare. C'est cette comparaison qui te dit si tu as tout saisi.
